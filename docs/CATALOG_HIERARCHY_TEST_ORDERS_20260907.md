# 商品／註記分層與 10 筆本機測試訂單

本批沿用 `codex/catalog-operations-20260907` 的正式風格介面，只調整使用者指定的商品與註記管理層級。完整介面重設仍留在 `codex/responsive-workflows-20260907`。本次沒有部署正式環境、修改遠端資料或變更資料庫 schema。

## 未分組的原因與正式環境判斷

- 商品的 `groupId` 允許空值；編輯商品選「不分組」就是合法的分類內商品，不是損壞或遺失資料。
- 「未分組商品」是前端依空值收集的系統清單，沒有群組 ID，所以不能重新命名、停用或編輯群組。實際商品仍可正常編輯，在「群組」欄位選擇目標即可歸組。
- 本機檢查：4 個分類、15 項商品，未分組商品 **0 項**。原介面卻無條件在每個分類插入一個空入口；桌面側欄與手機目錄都有相同行為。
- 已改為只有該分類存在未分組商品時才顯示，並加上「系統清單」與歸組方法。真實群組即使沒有商品仍保留，讓商家能繼續編輯與加入商品。
- 正式環境也可能存在沒有指定群組的商品，應按資料顯示相同系統清單。本次未查詢正式環境的私有商品資料，不能以本機 0 項推論正式也是 0 項；上述結論是資料與程式的行為判斷。
