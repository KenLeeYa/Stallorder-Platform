# Native delivery transaction settlement

This preparation adds a transaction lease to the exact native Apply SQL. It does not install or authorize a Primary writer. The earlier local PID-signal candidate was withdrawn before any push or hosted execution; its tests are not evidence for this replacement.

The protected caller must persist an authenticated intent containing the exact target, source and random positive signed-63-bit lease key before spawning one non-reconnecting native client. The writer enters the existing transaction, sets READ COMMITTED and a 15-second idle-in-transaction timeout, retains the original migration-history lock, and acquires the transaction advisory lock. It returns native same-session identity and lock evidence before the parent may send the unchanged migration/CAS remainder once. All original preimage, migration, history and postimage bytes remain intact.

After an interrupted writer, actual local child exit is required. A separate authenticated connection enters READ COMMITTED READ ONLY, waits for the same transaction lease, and then executes the complete state snapshot as a separate SQL statement while holding the lock. This statement boundary is necessary because READ COMMITTED takes its snapshot when each statement begins. A lock timeout, missing sender-exit proof or vanished parent runner leaves the operation unresolved; it never proves rollback or authorizes a retry. No backend signaling is used by the new helper. These semantics follow the [PostgreSQL 17 isolation](https://www.postgresql.org/docs/17/transaction-iso.html) and [transaction advisory lock](https://www.postgresql.org/docs/17/explicit-locking.html#ADVISORY-LOCKS) contracts.

The returned complete snapshot still requires exact classification against the authenticated baseline and qualified postimage. `originVerified`, `retryAllowed`, `mutationAuthorized` and `releaseAuthorized` remain false. A future remote caller must also bind the same database, transaction/session pooler mode, immutable source, protected intent, sender lifecycle and single-writer exclusion. Statement pooling and recovery after loss of the parent without sender-exit proof are outside this qualification.
