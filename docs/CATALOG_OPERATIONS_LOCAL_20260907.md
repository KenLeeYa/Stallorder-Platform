# 商品、預約與桌位 QR 本機驗收（2026-09-07）

本批為顧客確認後的新增功能，僅在獨立本機環境實作。正式環境緊急訂單修復及先前 3017 體驗版維持原狀。本文件是本次需求、功能連動及驗收的專屬紀錄；先前功能見 [本機訂單體驗](LOCAL_ORDER_EXPERIENCE_20260907.md)。

## 已確認的行為

| 功能 | 介面與規則 |
| --- | --- |
| 最後點餐時間 | 「營業時間」可逐星期設定 QR 最後點餐時間；特殊營業日可另設。留空沿用營業時段。到達截單時間後，新 QR 點餐顯示「超過最後點餐時間，請至櫃檯詢問」。既有訂單查詢、重送與修改沿用原授權，不當作新訂單。 |
| 預約範圍 | 「外帶自取」的最多預約天數採今天加 N 天，含最後一天：9/1 設 7 天可選至 9/8 當日允許時段，非滾動 168 小時。 |
| 特殊日期 | 特殊店休完全阻擋新預約；特殊營業時間取代一般時段，包含原本未營業時段。顧客、店員時間提案與伺服器驗證共用資料庫日曆。 |
| 庫存 | 每攤位、每商品的可售份數，空值為不限量，0 為售完。套餐按整份 SKU 計數，不扣食材或套餐內單品；備料不應重複填入整份及原料庫存。 |
| 扣補 | 訂單成立即占量，包含外帶預約。未製作的修改只計差額；未製作取消、拒單或過期回補。訂單、明細或 KDS 任一已開始製作即不回補。教學測試訂單不扣庫存。 |
| 補貨 | 店員選「增加補貨」加量；「設定剩餘」用於盤點。啟用計數前已成立的訂單不追扣、不因取消憑空回補。沒有午夜自動歸零／重設。 |
| 已售完 | 一鍵檢視手動售完與庫存為 0 的商品；可複選整群組批次售完、恢復／停止／開放供應。補貨不會自動解除手動售完。 |
| 商品管理 | 共用商品頁的平板／電腦版採分類群組側欄及整批商品清單；手機保留逐層目錄，另有直接進入庫存、已售完的入口。批次操作必須先選攤位；編輯主檔則影響全部共用攤位。 |
| 成員權限 | 原本已有停用角色能力，改名為「移除權限」並說明影響；不刪帳號及歷史紀錄。其他攤位／組織管理角色要分別處理。 |
| 線上 Menu | 移除「以下為目前公開菜單；實際供應、價格與客製選項以送出訂單時為準。」 |

## 已查明的 QR 與時間連動問題

1. 舊「輪替主要 QR」撤銷全部攤位 QR，包含已印出的桌位 QR；查詢最新 QR 亦未區分桌位。修正主要 QR 的選取、輪替與撤銷 session 範圍，只處理沒有桌位、地點、活動、行程及指定履約情境的主要 QR。
2. 先暫停再關閉後按「開放」，原程式只更改攤位狀態，QR 仍停在 PAUSED。OPEN 現在恢復尚未到期的 PAUSED QR；REVOKED 永不自動恢復。
3. 原始預約日曆只生成每週時段且上限使用 now + N 天，最後一天晚間與特殊加開時段會遺漏。
4. 舊 special-closure preflight 只看日期是否存在，連特殊營業也當店休。現在比較該日開放區間，並保留原 canonical auth、tenant、限流、重送和原訂單回復優先順序。
5. 截單判斷必須跨過打烊仍有效，直到下一營業時段，避免 18:40 截單但 19:00 又能送出。

以上是本機原始碼及可重現路徑的修正；不代表已從正式環境還原使用者當次掃碼的完整操作歷史。正式環境先前已撤銷的紙本 QR 不會因此自動恢復；不應為了復原而重新啟用已撤銷憑證。

## 庫存交易與連動

- PostgreSQL deferred constraint trigger 在交易結束時讀取最終明細，處理修改訂單刪除／重建明細的情形；每商品鎖定庫存列，並保存每訂單的已占用快照。
- 新訂單、QR、外帶、外送與店員開單共享同一交易層；價格、付款、折扣與訂單狀態仍由既有伺服器流程裁定。
- 不足時整筆回滾，顧客／店員收到 PRODUCT_STOCK_INSUFFICIENT，無半筆訂單或部分扣量。
- 管理 API 為 MANAGE_PRODUCTS + CSRF + organization/stall scope，批次最多 500 項。每列附 expectedVersion；並行成交或店員調整使版本不同時，全批拒絕並提示重新讀取，防止舊畫面蓋掉新庫存。
- 公開快取菜單額外讀取目前 0 庫存商品；Edge 直接讀取 stock_remaining。舊畫面下單仍由交易層阻擋超賣。
- 複製攤位商品設定不複製庫存，避免把另一攤位實物數量錯當本攤位庫存。營業時間範本會一併複製最後點餐時間。
- 已取消未製作訂單只回補一次。已製作退款、結帳或完成不回補，也不觸發新單提示音；提示音規則沿用上一批已實作內容。

## 設定前提醒

| 操作 | 提醒／限制 |
| --- | --- |
| 內用未開，列印桌位 QR | 預覽顯示尚未開放的原因，列印時再確認；可先印、之後開啟沿用同一 URL。 |
| 暫停／關閉／全攤售完時列印 | 提醒顧客掃描暫時不能點餐，需確認營運狀態。 |
| 關閉內用 | 提醒紙本桌位 QR 暫停服務，開啟後可沿用。 |
| 關閉外帶預約／外送 | 提醒不再收新單，既有單仍需處理，不自動取消。 |
| 改預約天數／間隔 | 提醒影響新預約與時間提案，不自動修改既有單。 |
| 新增特殊店休 | 提醒檢查既有預約並聯絡顧客；既有顧客提醒與追蹤採上一批功能。 |
| 補貨後恢復供應 | 明示手動售完、主檔停用及供應時間仍各自限制，不以補貨覆蓋其他開關。 |
| 移除角色 | 確認撤銷此角色，保留歷史；其他角色可能仍給予存取。 |
