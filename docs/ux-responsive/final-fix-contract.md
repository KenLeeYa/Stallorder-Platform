# Responsive final review fixes: local contract

This is a local candidate, not release approval. I1–I6 and M1 are the scope; full acceptance/performance and physical/provider gaps in the B3 report remain.

- Cash: existing-order checkout retains numeric change and now exposes shortage independently; both consumers display 100 due / 60,100,120 received as shortage40 / exact0 / change20.
- KDS: board GET401/403/404 clears snapshot, stations, reservations, selection and cancellation. A denied PATCH immediately invalidates older snapshots and rechecks board access. Denied writes or lost read access keep actions locked until the page re-resolves permissions; GET200 alone is not proof of write access. A missing task404 with a readable board remains distinct.
- POS: a minimal recovery marker contains only version, org/stall/actor identity, original idempotency key, payment timing, cash boolean and original draft ID. It is persisted/read back before online dispatch, under a Web Locks transaction lock. Browser storage or Web Locks failure prevents a new online dispatch. Existing offline behavior is unchanged for eligible requests observed offline before dispatch, provided no unresolved online marker exists. No payload/customer/contact/notes/token/payment amount is stored in this marker.
- An existing marker cannot be overwritten by a different attempt/tab/actor. Original-actor recovery uses GET `/api/stalls/[stallSlug]/orders/recovery?actorProfileId=<uuid>&idempotencyKey=<uuid>`, existing CREATE_ORDERS authorization and the same STAFF_POS idempotency owner. Server-resolved organization/stall, authenticated actor hash and original key constrain the read. No schema, payment, entitlement, print or transaction writer changed.
- FOUND returns the existing serialized order. UNKNOWN includes a never-accepted request, a marker saved just before a crash, or an ongoing request; none is evidence that replacement is safe. Denial, malformed response and network failure remain locked. Users can reauthenticate as the original operator, retry a read, or return to the board for manual review while retaining the marker/reference. Returning does not unlock draft restoration or new POS creation. Clearing is limited to authoritative FOUND or a known initial nonaccepted response before uncertainty. The exact original draft is consumed on FOUND.
- Uncertain POST replays (including automatic replay) were removed because the authenticated actor could change between attempts. The eight Q03 cases now exercise read-only recovery; they are changed-semantic regressions, not reused historical POST-replay evidence. PAY_LATER describes uncertain order creation instead of collection.
- Explicit localized test-order labels appear in phone summaries and detail, independently of source and workspace flag.
