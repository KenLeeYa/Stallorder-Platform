# 單一註記子視窗返回修正（本機）

使用者回報：從「所有單一註記」點選「不加胡椒」等細項後，清單消失，子視窗背景變成共用商品主頁。本次修正位於 `codex/catalog-operations-20260907`，基準為 `b6ec117`，僅更新 3018 本機。

## 原因與修正

`leaveReusableNoteNavigator` 在開啟細項或新增視窗前，直接關閉父清單並清空搜尋。舊的 CRUD 測試 helper 會重新開啟清單，因而沒有驗證使用者實際返回的位置。新增回歸案例在修正前確實失敗於「清單不存在」。

現在父清單維持掛載，使用獨立的視窗 ref，保留搜尋與捲動位置；子視窗開啟時，父層暫停 Escape／Tab 處理並從輔助技術的可操作對話框中隱藏。關閉子視窗回到原項目，成功或錯誤回饋關閉後聚焦清單搜尋。只有關閉父清單才退出至共用商品主頁。

WebKit 的按鈕點擊未必自動聚焦，入口、新增與註記卡片會明確聚焦發起按鈕，讓子視窗關閉後能回到同一控制項。瀏覽器案例在頁面載入穩定後開始點擊，不使用自動重按或重開清單來掩蓋失敗。

本次沒有修改 API、資料庫規則、商品價格或既有訂單。

## 驗證

- `reusable-note-navigation-local.spec.ts`：320／390／768／1440 的細項、編輯、新增、X、Escape、Tab、搜尋、捲動與焦點；直接驗證原清單存在，不重新開啟入口。
- `product-note-groups.spec.ts`：群組 CRUD、共用／專用排序、多筆加入、共用註記多群組同步、重名錯誤、使用中禁止刪除與匯入／匯出；加驗單一註記上下移、啟停、取消刪除、503 回饋與成功返回。
- 多個保留的範例工作區仍可正常選擇；測試登入明確指定原商家，切換至群組流程時明確關閉單一註記清單。

結果：Chromium 四種寬度 4 項、WebKit 四種寬度 4 項、原有註記管理流程 5 項，共 13 項瀏覽器案例通過；相關 2 檔／8 項契約測試、ESLint、TypeScript 與完整 `npm run build` 通過。Windows 執行中的 Prisma DLL 曾阻擋產生步驟，短暫停止本工作區的 3018 後完成編譯，並已重啟 development 服務。未修改資料庫程式，本次未重跑整套 SQL 測試，也未部署正式環境。

執行結果與截圖位於同一任務的本機證據目錄，檔名為 `note-navigation-*`。先前全系統 QA 數量屬於上一版證據，本次僅重跑本修正相關案例。
