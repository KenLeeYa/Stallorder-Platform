## 印表機與工具列

- 原因：自動列印代理自行顯示連線橫幅，但上方列印佇列連結固定為一般樣式，兩者沒有共享當下狀態。
- 改為由同一代理回報狀態給現有圖示；成功的實際 webPRNT 無內容探測後反綠，樣式與聲音／保持喚醒一致。成功／檢查中的文字保留給輔助技術，不占看板高度。
- 缺紙、開蓋、斷線、逾時、SDK／瀏覽器不支援及未設定印表機仍保留明確提示；下一次探測成功恢復反綠。已連線但沒有自動出單規則時，綠色圖示帶警示點，並保留規則設定說明。
- 瀏覽器能力、Bluetooth 配對、歷史 heartbeat 都不能單獨當成成功連線證據；本次不修改列印工作、付款、KDS 或完成訂單的判斷。
- 測試發現原 `sm:overflow-x-visible` 在 768px 讓右側鎖屏通知圖示伸出工具列，再被父層裁掉，實際點擊失敗。移除該斷點覆寫，放不下時保留工具列橫向捲動；長者模式仍使用原功能選單。
- 長者模式功能選單曾在子視窗完成掛載前自行關閉，連帶卸載鎖屏通知視窗；現在依 `aria-haspopup="dialog"` 明確保留開啟子視窗的入口，不再用計時器猜測掛載時序。

## Android 音效：已知與待確認

使用者回報 OPPO Reno11 5G、Android 16、Chrome 瀏覽器分頁已能顯示鎖屏通知，但沒有音效；另已確認網站設為快訊／響鈴且有鈴聲。因此不能將原因直接歸為通知類別靜音，仍需核對新版 worker、通知音量／勿擾、Chrome 與 ColorOS 行為。iPad 本輪未實測。

原程式未指定 `silent`，採平台預設。現在明確傳 `silent: false`；不同新單各自要求通知音效，重試同一通知仍去重，維持 `renotify: false`。此參數不是繞過手機靜音、勿擾或通知類別的手段，不能據此宣稱實機音效已修好。通知 API 沒有可指定網頁自訂 MP3 的標準 `sound` 參數。[Notifications 標準](https://notifications.spec.whatwg.org/)

重新連結與「30 秒後測試通知」會檢查 **active** Service Worker 是否回報非靜音能力。僅下載了新版、但舊版仍運行時，先提示完成更新，不排定測試。保留既有離線待同步資料檢查，不強制 `skipWaiting`。測試仍由伺服器排程，前景音效、新單才通知及簽章顯示回報的規則不變。

鎖屏通知視窗增加可展開的「收到通知但沒有聲音」指引：

1. 長按實際收到的通知，進入該網站的通知類別，確認為快訊／響鈴且鈴聲不是無；ColorOS 顯示名稱可能不同。
2. 檢查通知／鈴聲音量、靜音與勿擾。媒體音量與通知音量不同。
3. 若連續大量測試才變安靜，檢查裝置是否提供通知冷卻功能。
4. 完成網站更新後，按「30 秒後測試通知」並鎖屏；分別觀察顯示、聲音及點擊返回。

Android 官方說明：快訊與靜音可分別設定；通知冷卻可降低密集通知的聲音干擾。實際選單依製造商而異。[通知設定](https://support.google.com/android/answer/9079661?hl=zh-Hant)

若更新後、通知音量正常且沒有勿擾仍無聲，需用這台 OPPO 比較其他 Chrome 網站及一般 App 的通知，才能繼續區分 Chrome 通知類別與 ColorOS 系統行為；伺服器顯示回報無法量測喇叭是否發聲。目前等待新版的鎖屏測試結果。
