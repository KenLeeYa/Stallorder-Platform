# Supply Lite 架構

## 範圍

- 食材與基本單位。
- 中央／攤位庫位。
- 商品配方與耗損比例。
- 收貨、耗用、調整、盤點、移轉與沖銷 ledger。
- 庫存餘額與移動平均成本。

## 一致性

- `supply_inventory_movements` 為不可變 ledger。
- `organization_id + idempotency_key` 唯一。
- 異動在 transaction 與 advisory lock 內更新 balance。
- 庫存不足不會被靜默修正；需明確規則或人工調整。

## 商品配方長清單

- `/merchant/supply` 的商品配方毛利與配方項目各自搜尋、每頁顯示 6 件；毛利按商品名稱搜尋，配方項目按商品或食材名稱搜尋。搜尋涵蓋已載入的整份清單，保留原排序及既有編輯／移除入口。
- 清單顯示目前資料件數、符合件數與頁碼；搜尋／清除搜尋回到第一頁。成功異動取得新的 dashboard 後兩份清單回到第一頁，組織切換則清除搜尋、頁碼與已開啟對話框。
- 尚未建立配方的商品仍可搜尋、翻頁查看；毛利區持續顯示整份已載入清單的未建配方數及個別警示，不因分頁遺失提醒。
- 此為前端呈現分頁，不是資料庫游標分頁或方案額度。`getSupplyDashboard` 既有查詢上限維持商品 1,000 件、配方項目 5,000 件；超出上限的資料不在本次搜尋範圍。
- 入口與 API 維持 `MANAGE_SHARED_PRODUCTS` 權限及 `MODULE_SUPPLY_LITE_ENABLED` 檢查。商品／配方依組織讀取，庫位、餘額及異動維持既有授權攤位範圍；前端不增加資料權限。
- `supply-lite-manager.pagination.test.ts` 以實際 React 元件及 Chromium 驗證搜尋、分頁、鍵盤操作、缺配方提醒、末頁移除後刷新與跨組織重置；API 使用記憶體回應。完整樣式、實際登入／API／DB 與手機畫面仍需由本機整合 QA 驗證。

## 庫存與歷史長清單

- 批號、食材／包材／耗材／器具、廠商、庫位、最近進貨單與最近庫存流水各自先顯示 6 筆。「顯示更多」每次增加 6 筆，「收合」回到前 6 筆；保留服務端原有排序、完整已載入件數與目前顯示件數。
- 展開狀態互不影響；成功異動刷新 dashboard 與切換組織後均重置。原有編輯／停用按鈕仍依資料 ID 操作；進貨與流水維持不可直接改刪的提示。
- 低庫存件數與批號差異提醒仍依完整已載入資料計算。批號區另顯示所有已載入批號的逾期及 7 天內到期數，依服務端 `asOfDate` 判斷，不因收合隱藏風險總數。
- 查詢上限及權限不變：批號 1,000、品項 500、廠商 500、庫位 200、最近進貨單及流水各 50；展開不另外讀取服務端資料。元件測試以每區 25 筆驗證實際顯示數、展開／收合、完整提醒、組織重置與展開後精確操作 ID。

## 非目標

不做採購審批、應付帳款、供應商結算或大型 ERP；ERP 只預留可驗證的匯出／匯入 Adapter。
