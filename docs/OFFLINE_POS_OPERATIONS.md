# 離線 POS 營運手冊

## 開店前

1. 管理者在攤位離線設定啟用單一裝置模式。
2. 登錄店員裝置，核准並指定唯一 Offline Leader。
3. 店員在線登入，開啟現金班別並完成離線 bootstrap。
4. 確認儲存能力、Permit 剩餘時間、菜單版本與待同步筆數。
5. 先做一筆非營業測試單，確認同步與列印狀態。

## 斷線中

- 只有 Leader 可新增外帶訂單。
- 可用快照菜單、本機 KDS、現金與核准的人工付款。
- Provider 付款、退款、新開班、跨攤位、團隊及訂閱異動不可用。
- 保留頁面與裝置電源，不清除網站資料、不登出、不移除 PWA。
- 注意待同步筆數、最舊資料時間、Permit 與儲存警示。

## 恢復連線

1. 系統自動同步；必要時按「立即同步」。
2. 等待「目前沒有待同步的本機訂單」。
3. 核對正式訂單編號、現金班別與列印工作。
4. 管理者處理所有 OPEN conflict 並留下原因。
5. 完成對帳後才關閉或更換 Leader。

## 禁止操作

- 不要清除瀏覽器資料或解除安裝 PWA。
- 不要讓第二台裝置同時離線收單。
- 不要把人工 LINE Pay／街口紀錄當作 API 授權成功。
- 不要在未知列印狀態直接重印。
- 不要以刪除本機資料或衝突取代核對。

## 緊急處理

Permit 到期或裝置被撤銷：停止新單，保留既有資料並恢復網路。

儲存空間警示：停止新增離線單，優先同步，不清除 IndexedDB。

同步持續失敗：記錄畫面上的固定錯誤代碼、裝置名稱、攤位與發生時間；不得
截圖或傳送 Permit、Session、顧客聯絡資料。

遺失裝置：管理者遠端標記遺失並撤銷 Permit，再指定新 Leader。舊裝置資料
仍需依事件流程追蹤，不假設遠端撤銷會抹除 IndexedDB。
