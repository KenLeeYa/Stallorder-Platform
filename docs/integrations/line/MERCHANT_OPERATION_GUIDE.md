# 商家使用平台 LINE 通知

2026-09-27。本機候選；正式未開啟。所有合作店通知由攤點通平台 OA 發出，內容標明實際店名/分店。LINE Pay 仍由各店原商家帳戶收款。

## 製作完成在哪裡操作

使用原 /staff/{stallSlug} 店員看板或原 KDS。開始製作、單品完成、整單製作完成維持原流程。只有所有有效餐點符合原 READY 規則才排可取餐通知；打包中、部分完成、已付款、已印單不會冒充全部完成。

## 交付餐點

原店員看板「平台 QR 掃碼交付」→開相機/掃描器貼碼→「預覽餐點與付款」。先核對門市、品項、付款；真的交付後才確認「交付／完成取餐」。只有一次原單完成與計費，不因重掃多計。

相機不可用可進「人工核對／憑證管理」，選本店訂單、核對短碼/顧客、填原因；仍須 READY/已付款且無 UNKNOWN。預覽或看QR不交付。離線不當成功，重新連線查原結果，不另開新單。

過期/改時間/撤銷票據：授權店員查看現有版本、填原因再重發，可有界延展；舊碼永久失效。現金未收先走原收款。取消/退款與交付會以原單鎖序列化，無法繞過付款狀態。

## 顧客沒收到通知

本店管理者開 /merchant/{stallSlug}/notifications；平台管理者開 /admin/line-platform。查通知狀態、用途及摘要：

| 顯示 | 處理 |
|---|---|
| 尚未確認好友/不同意通知 | 引導顧客在本人訂單頁查看，不保證一定收到 |
| LINE 已接受 | 平台 API 已接受，不代表顧客已讀/送達 |
| 等待重試 | 系統沿原 key/body恢復；勿另送同事件 |
| 配額不足/停用 | 聯絡平台查方案/配額，不改用本店 OA |
| 人工查核 | 平台先核實未知結果，不任意換 key重送 |
| 可安全重試 | 有本店權限者填原因；冷卻/用途/24h規則仍限制 |

已取餐/已取消的單不能補發過時 READY；通知失敗不需要取消訂單。店家不能輸入任意顧客 LINE ID 或平台密鑰。

## 付款問題

/merchant/payments「LINE Pay 付款查核與退款」按門市查看。UNKNOWN 先查核，不要求客人再次付款。退款需原管理權限、原因、確認金額，server驗原收款商家/可退餘額；部分退款僅在能力開放時可用。詳見 PAYMENT_OPERATIONS.md。
