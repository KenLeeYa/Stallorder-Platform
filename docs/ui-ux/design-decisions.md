# Phase 02–03：設計決策

## 導覽選項

| 方案 | 優點 | 代價 | 決策 |
|---|---|---|---|
| 全面側欄 + Kanban | 狀態清楚、桌面可掃描 | 平板寬度不足、換整個結帳 context，風險高 | 不採用 |
| 既有三欄工作台 + 可計數篩選 + 緊湊工具 | 維持熟悉位置、明確主動作，既有權限/controller 可重用 | 需要處理窄屏、分頁與篩選選取一致性 | 採用 |
| 單欄所有訂單與全部操作 | 手機不用學新結構 | 長清單重複資訊、低頻功能占版面 | 手機僅保留有限清單，其他裝置不採用 |

## 相容與風險界線

- 工作台篩選是 read model，不產生新的後端狀態，不把「列印成功」推導為「訂單完成」。取消／已完成仍走既有區域與 server 規則。
- 正常新單→已接單→製作/包裝→待取/待送；異常篩選可與上述狀態重疊，須明說不能相加。
- 預設每頁 5 筆，沿用專案清單規則；待處理總數不因分頁隱藏。頁碼超界自動夾回；新單更新保持合法選取；不把跨頁未見訂單批次操作。
- 保留現有安全重試、confirmation、audit 與批次結果，不為統一視覺而換掉付款／退款／重印／開錢櫃確認。
- 不以寬度 alone 判斷角色，不改登入預設頁／tenant 邊界。不啟動未開通的供應鏈、impersonation 或外部支付。
- 新字串進入現有六語字典；商品資料翻譯仍由既有 server 動態資料管線處理。
- 不新增 runtime 依賴。原有 light/dark 與 senior 持續相容；使用 semantic tokens 漸進套用，不一次覆寫全部 Tailwind 色彩。

正式發布、feature flag 部署、密鑰與外部服務設定留人工清單；獨立分支可供本機驗收，未等於已上線。
