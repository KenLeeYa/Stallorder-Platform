# 資訊架構

## 比較方案

| 方案 | 優點 | 風險／成本 | 決策 |
|---|---|---|---|
| 全站側欄＋完整 Kanban | 模組顯眼、看製作階段 | 平板橫向壓縮；長訂單重複；付款／列印不適合單一流水欄 | 不採用 |
| 現有工作模式＋三區工作台＋篩選分頁 | 保留操作記憶與 controller，可小批驗證 | 跨頁批次必須清楚標示範圍 | 採用 |
| 全部變單欄大卡片 | 手機易操作 | 桌機浪費空間，長清單成本高 | 僅手機延續現有單欄 |

## 模組與入口

- 顧客：Menu → 模式／時間 → 餐點／客製 → 購物車 → 結帳資料 → 原訂單追蹤。會員為可選入口。
- 店員：工作工具列 → 搜尋（涵蓋所有在案訂單）→ 工作狀態篩選 → 清單／品項／操作；已完成查詢與未來預約維持獨立。
- 廚房：既有工作模式、製作站、批次品項；不套用 merchant 的管理按鈕。
- 商家：儀表板、商品、攤位、報表、庫存、人事、成長、整合、帳務、帳號；每個入口沿用 server 提供的 capability 與角色條件。當前模組以文字與 aria-current 標出。
- 平台：既有 billing／health／audit 等分區；沒有新增隱藏切換租戶、代登入或未接線功能。

## 分頁／返回契約

店員與商品頁初始 5 筆。搜尋仍跨整個已載入集合，切換篩選回第 1 頁；刪減資料後頁碼夾限到合法頁。訂單更新不重排 server 的既有優先順序，選取單仍在本頁時保留選取。商品全選只選本頁可操作商品，已選集合可跨頁累積；更換攤位、分類、群組、搜尋會清除選取，避免誤操作隱藏集合。

現有 NavigationStateManager 繼續處理路由／捲動；本輪沒有把訂單篩選寫入 URL，避免把任何顧客資料帶入網址。跨重新整理保留篩選不在目前實作範圍，列於 backlog。
